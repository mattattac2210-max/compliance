## STEP 1 — Database schema (`shared/schema.ts`)

Add two new tables. Run `npm run db:push` after.

### `vault_document_templates`

Master list of documents required per gate. Seeded, not user-editable.

```typescript
export const vaultDocumentTemplates = pgTable("vault_document_templates", {
  id: varchar("id").primaryKey().default(sql`gen_random_uuid()`),
  gateNumber: integer("gate_number").notNull(),     // 0–7
  documentSlug: text("document_slug").notNull().unique(),
  isRequired: boolean("is_required").notNull().default(true),
  expiryMonths: integer("expiry_months"),           // null = no expiry / permanent
  translations: json("translations").$type<Record<string, { name: string; description: string }>>().notNull(),
  isActive: boolean("is_active").notNull().default(true),
});
```

### `vault_documents`

One row per property per template — tracks each document’s status.

```typescript
export const vaultDocuments = pgTable("vault_documents", {
  id: varchar("id").primaryKey().default(sql`gen_random_uuid()`),
  propertyId: varchar("property_id").notNull().references(() => properties.id, { onDelete: "cascade" }),
  templateId: varchar("template_id").notNull().references(() => vaultDocumentTemplates.id),
  status: text("status").notNull().default("missing"),  // missing | uploaded | expiring | expired
  expiryDate: text("expiry_date"),                      // ISO date string, null if no expiry
  uploadedAt: text("uploaded_at"),
  fileUrl: text("file_url"),                            // placeholder for future file upload
  notes: text("notes"),
  updatedAt: text("updated_at").notNull().default(new Date().toISOString()),
});
```

Export Zod schemas and types for both tables.

## STEP 3 — API routes (`server/routes.ts`)

All routes require `requireAuth` middleware.

### Vault templates (public reference data)

```
GET /api/vault/templates
→ Returns all active templates, ordered by gateNumber
→ No auth required (public reference)
```

### Vault documents (per-property, per-user)

```
GET /api/vault?propertyId=:id
→ Returns all vault_documents for that property
→ Verify property belongs to req.session.userId
→ Auto-computes status: if expiryDate exists and is < today → "expired", < 90 days → "expiring"

POST /api/vault
→ Body: { propertyId, templateId, status, expiryDate?, fileUrl?, notes? }
→ Upsert (update if exists for that propertyId+templateId, create if not)
→ Set updatedAt

PATCH /api/vault/:id
→ Update status, expiryDate, notes, fileUrl
→ Verify via property ownership

GET /api/vault/summary?propertyId=:id
→ Returns: { total, uploaded, missing, expiring, expired, completionPct, gateCompletions: [{gateNumber, pct}] }
```

### Data logic

```typescript
// Load templates once (public)
const { data: templates = [] } = useQuery({ queryKey: ["/api/vault/templates"] });

// Load user's vault docs for selected property
const { data: vaultDocs = [] } = useQuery({
  queryKey: ["/api/vault", selectedPropertyId],
  queryFn: () => fetch(`/api/vault?propertyId=${selectedPropertyId}`).then(r => r.json()),
  enabled: !!selectedPropertyId,
});

// Compute status for display:
// - If vault doc exists → use its status
// - If no vault doc yet → "missing"
// - Override: if expiryDate < today → force "expired"
// - Override: if expiryDate < today + 90 days → force "expiring"
```

### Auto-status computation (do this on the backend in the GET /api/vault route, not just frontend)

When returning vault documents, compute status dynamically:

```typescript
const today = new Date();
const ninetyDays = new Date(today.getTime() + 90 * 24 * 60 * 60 * 1000);
if (doc.expiryDate) {
  const expiry = new Date(doc.expiryDate);
  if (expiry < today) doc.status = "expired";
  else if (expiry < ninetyDays) doc.status = "expiring";
}
```

## CONSTRAINTS

1. **Never hardcode English in JSX** — always `t.vault.*`, `t.timeline.*`, `t.alerts.*`
1. **Match DSCVR design language exactly** — gate colours, CSS custom properties, Montserrat/Lato fonts, dark navy background, teal accents
1. **Vault status is computed dynamically** — both backend (on GET) and frontend (for display). The `status` field in the DB is the operator-set status; the displayed status overrides it based on expiry date math
1. **Do not break Phase 1** — login, register, profile, and all existing compliance flow must continue to work
