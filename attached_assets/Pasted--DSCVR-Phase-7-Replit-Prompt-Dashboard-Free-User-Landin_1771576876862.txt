# DSCVR — Phase 7 Replit Prompt
## Dashboard: Free User Landing + Pro User Dashboard

---

## CONTEXT

Phases 1–6b are complete. The current `/app` landing drops all users — free and Pro — onto the Compliance Flow tab with three 0% stat cards and no orientation. This phase replaces that with two distinct, purposeful landings.

**The free/Pro split:**
- **Free** = authenticated (`isAuthenticated: true`) but `isPro: false` and `isAdmin: false`
- **Pro** = `isPro: true` OR `isAdmin: true`
- **Unauthenticated** = not logged in — already handled by the marketing landing page, not this phase

**Stack:** React 18 + TypeScript + Vite + Wouter + Express 5 + Drizzle ORM + PostgreSQL + shadcn/ui + Tailwind + Framer Motion. Three languages: `en`, `uk`, `id`. **Never hardcode English strings in JSX.**

---

## ARCHITECTURE

The `/app` route renders the `AppShell` (sidebar + topbar) with a content area that shows either:
- `<FreeDashboard />` — when `!isPro && !isAdmin`
- `<ProDashboard />` — when `isPro || isAdmin`

Both components live in `client/src/pages/dashboard/`:
- `client/src/pages/dashboard/free.tsx`
- `client/src/pages/dashboard/pro.tsx`
- `client/src/pages/dashboard/index.tsx` — router that picks between them

```typescript
// client/src/pages/dashboard/index.tsx
import { useAuth } from "@/hooks/useAuth";
import FreeDashboard from "./free";
import ProDashboard from "./pro";

export default function Dashboard() {
  const { user } = useAuth();
  if (user?.isPro || user?.isAdmin) return <ProDashboard />;
  return <FreeDashboard />;
}
```

The existing Compliance Flow / Self-Audit / Guidebook tab content moves into sub-components:
- `client/src/components/compliance-flow.tsx` — extracted from home.tsx
- `client/src/components/self-audit.tsx` — extracted from home.tsx
- `client/src/components/guidebook.tsx` — extracted from home.tsx

Both dashboards can import and embed these components directly — no routing changes needed.

### B3 — Setup progress banner

Show only when `setupScore < 4`. Same 4-step logic as Phase 6b spec, computed from:

```typescript
function getSetupScore(property: Property, vaultSummary: VaultSummary): number {
  let score = 0;
  if (property.propertyName?.length >= 4 && property.entityName?.length >= 4) score++;
  if (vaultSummary.uploaded > 0) score++;
  if (property.entityStructure && property.entityStructure !== "unknown") score++;
  if (property.selfAuditStartedAt) score++; // set in localStorage or property field
  return score;
}
```

Banner:
```
GET SET UP — Step {n} of 4 complete

[●●●○]  Step 1: Property profile ✓  Step 2: First vault document ✓
         Step 3: Entity structure ✓  Step 4: Run self-audit ○

[→ Complete Step 4: Run Self-Audit]
```

Dismiss button (×) stores dismissedSetupBanner in localStorage per userId. Even if dismissed, the banner reappears if score drops back (e.g. property deleted and recreated).

i18n keys: `t.dashboard.setupHeading`, `t.dashboard.setupStep1..4`, `t.dashboard.setupStepComplete`, `t.dashboard.setupStepNext`, `t.dashboard.setupContinue`

### B4 — Four stat cards

**Data sources:**
- Vault progress: `GET /api/vault/summary?propertyId=:id` → `{ completionPct, uploaded, total }`
- Expiring docs: same summary → `{ expiring }` (docs expiring within 90 days)
- Filings due: `generateUpcomingFilings(1)` filtered to current month → count
- Active alerts: `GET /api/vault?propertyId=:id` → count of `status === "expired"` + overdue filings

**Card states:**

| Metric | 0 / empty | > 0 (good) | > 0 (needs action) |
|--------|-----------|------------|-------------------|
| Vault % | neutral grey, "Start uploading" | teal progress | — |
| Expiring | neutral grey, "Nothing expiring" | amber if > 0 | red if expired |
| Filings | neutral grey, "None this month" | amber if ≤ 7 days | red if overdue |
| Alerts | neutral grey `✓`, "All clear" | — | red if > 0 |

Each card has a specific CTA linking to the right page. CTA text changes based on state:
- Vault 0%: "Upload first doc →"
- Vault > 0%: "Continue →"
- Expiring > 0: "View expiring →"
- Filings due: "View deadlines →"
- Alerts > 0: "View alerts →"

## PART E — DATA FETCHING

### Queries needed in ProDashboard

```typescript
// 1. Active property (already in AppShell context — reuse)
const { data: properties = [] } = useQuery({ queryKey: ["/api/properties"] });
const activeProperty = properties[0]; // or from a selected property context

// 2. Vault summary
const { data: vaultSummary } = useQuery({
  queryKey: ["/api/vault/summary", activeProperty?.id],
  queryFn: () => fetch(`/api/vault/summary?propertyId=${activeProperty?.id}`).then(r => r.json()),
  enabled: !!activeProperty?.id,
});

// 3. Vault documents (for "needs attention" panel)
const { data: vaultDocs = [] } = useQuery({
  queryKey: ["/api/vault", activeProperty?.id],
  queryFn: () => fetch(`/api/vault?propertyId=${activeProperty?.id}`).then(r => r.json()),
  enabled: !!activeProperty?.id,
});

// 4. Upcoming filings (client-side, no fetch needed)
import { generateUpcomingFilings } from "@/lib/filing-schedule";
const upcomingFilings = generateUpcomingFilings(3);

// 5. Staff (for BPJS gap check)
const { data: staff = [] } = useQuery({
  queryKey: ["/api/staff", activeProperty?.id],
  queryFn: () => fetch(`/api/staff?propertyId=${activeProperty?.id}`).then(r => r.json()),
  enabled: !!activeProperty?.id,
});
```

1. **Never hardcode English in JSX** — all strings via translation keys
2. **Free users always see the full compliance reference content** — it is never locked or hidden. Only the tracking tools (Vault, Timeline, Alerts) are Pro-gated.
3. **Pro dashboard is data-first** — no large marketing copy. Users paid; show them what's happening with their villa.
4. **Free dashboard is reference-first** — compliance flow content is the primary value, tiles are navigation aids.
5. **Zero states are calm and actionable** — 0 in any stat card is normal for a new user. Never show warning colours for zero.
6. **GlossaryAwareText** — wrap all compliance terms in panel content (SLF, BPJS, PB1, etc.) using the existing component.
7. **Do not break Phases 1–6** — all existing vault, timeline, alerts, profile, admin functionality continues to work unchanged.
8. **OTA deadline always visible** — it is the most urgent shared concern. Free users see it as a banner. Pro users see it in the upcoming deadlines panel.
9. **`generateUpcomingFilings` is client-side only** — no database query for the filing schedule itself.
10. **The compliance flow / self-audit / guidebook content is not duplicated** — extract existing components and import them into both dashboards. One source of truth.
